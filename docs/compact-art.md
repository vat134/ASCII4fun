# Compact Mini Art

Mini art is an independent workspace alongside Text and Media. Text and Media occupy two equal grid columns; Mini art spans the row below. It converts JPEG, PNG or still WebP to spatial Unicode Braille through the same C# engine in the browser, API, CLI and package. Each cell encodes 2 x 4 image samples; it is unrelated to the retired Media density ramp.

## Controls and destinations

Only Steam, Telegram, Twitch and File are supported. Steam has Comment (1,000 UTF-8 bytes), Summary (4,000) and Info box (8,000); the others each have one field. Telegram allows 4,096 characters; Twitch 500; File has no text budget. Switching destination or Steam field returns sizing to Auto. Four visible destination cards show shared-engine counts, budget meters, Fits / May wrap / Over limit guidance. Recommendations estimate external font wrapping; they are not calibrated device guarantees.

Columns show the resolved Auto value, one-column decrement/increment buttons and editable manual width (4..200). Height follows crop and destination cell proportions. Preview displays dimensions, counts, remaining/excess budget and the Auto recommendation. The neutral centered raster uses a maximum default scale of 0.75, including File; preview zoom does not change exported pixels. No simulated chat, device picker or social account connection is included.

Short choices use visible buttons: destination, Steam field, crop aspect, quarter-turn rotation, dither and Look. Crop has zoom and horizontal/vertical center. Tone controls include invert, brightness, contrast, gamma, detail, edges and auto levels. Photo, Texture, Sketch, Soft and Poster show actual thumbnails generated by the shared C# engine for the current source and settings. Look-only changes reuse those thumbnails; crop/tone/dither/destination changes regenerate them.

Empty cells always use Clean U+2800. There is no Blank cells setting or Windows-safe substitute. Twitch Copy/TXT has a blank lead-in row and space-separated Braille rows for single-message wrapping. Counts include destination formatting. PNG retains the rectangular artwork. External Windows fonts can render pasted blanks unevenly; exact compatibility needs real paste verification.

## Shared look implementation

All five looks are complete ports of MIT Typist `tone.js` and `dither.js` at commit `f128e782e33de2dcb013eb572a02e236851cc662`: alpha-weighted area reduction to a 1024px long side, integer summed-area luma, fractional crop footprints, Float32 stores with double arithmetic, guided base/detail split, saliency, weighted Otsu, region LUT, normalized detail, local feature push, bounded automatic gamma, background cleaning, snap, polarity-aware brightness, border-connected flat backdrop cleaning and thinned edge emphasis. Diffusion stores round like Float32Array.

ImageMagick decodes, orients, normalizes and renders. Shared C# owns fractional sampling and tone preparation for all five looks, without intermediate RGB byte rounding. Browser workers send one normalized source RGBA buffer to the same C# implementation used by native conversion. Fully transparent samples remain blank after edge/diffusion and Clean blanks remain U+2800. No subject model, extra control, runtime dependency or production JavaScript conversion is added.

Texture includes the original activity mask, weighted percentile normalization, Float32 CLAHE tables/interpolation, gated sharpening, target exposure and flat-region cleaning. Sketch includes the exact Gaussian kernel, XDoG, hysteresis, short-component pruning, padded-side suppression, capped shading, halos and polarity-specific line composition. Soft uses the original three-pass clamped blur, bounded sharpening, small-grid assistance (including manual mode), contrast and gamma solve. Poster includes original denoise/sharpen, Otsu split, rational sigmoid and endpoint snap. Shared numerical operations and the full fractional source sampler replace the retired approximations. The owner explicitly requires full reference behavior for all five looks.

## Native, API and CLI

`Ascii4Fun.Compact.CompactArtConverter.ConvertAsync(stream, options, cancellationToken)` returns `Canvas` and `Payload`. `CompactArtOptions` controls preparation/destination. Geometry is bounded to 40,000 cells and a 2,048-pixel sample side, limiting neighborhood-filter work on extreme aspect ratios; source admission uses existing still-image limits. Crop geometry retains fractional pixel dimensions and can extend beyond the source into transparent padding, matching the reference sampler. Cancellation propagates through read, decode, analysis, tone, dither and mapping. Media is not retained.

`GET /api/compact/options` returns defaults and destination metadata. `POST /api/compact/convert` accepts multipart `image` and `settings` JSON with the existing antiforgery token/header. The response contains rectangular text, dimensions, base64 PNG and destination payload. Invalid settings return 400, unsupported declared type 415 and undecodable sources 422.

```powershell
dotnet run --project src/cli -- convert-compact photo.png --destination steamc --output art.txt
dotnet run --project src/cli -- convert-compact photo.png --destination plain --width 48 --format png --output art.png
dotnet run --project src/cli -- convert-compact photo.png --settings compact.json --output art.txt
```

Settings JSON uses camel-case properties; omitted values retain defaults, unknown properties fail explicitly. Settings files are limited to 64 KiB. TXT is UTF-8 without an added trailing newline.

## Rendering and comparison evidence

The original Unifont Braille glyphs outline unraised positions, creating phantom marks despite correct encoded text. U+2800-U+28FF now use bundled, unmodified Noto Sans Symbols 2 v2.008 (OFL 1.1) through existing native/browser ImageMagick glyph adapters, at 24px / baseline 18. Raster tests check all 256 patterns against unions of only their raised single-dot masks, including blank cells and the lower dot row. Font provenance is in [fonts/README.md](../src/engine/rendering/fonts/README.md). Look SVG thumbnails use fixed per-character x coordinates to avoid blank-glyph advance drift; the main raster uses fixed 12 x 24 cell origins.

Exact look comparison uses identical decoded RGBA, crop, grid, controls and dither. Decoder/color-management differences and external font metrics are separate boundaries. The committed oracle is produced directly from hash-checked original JS, using authored synthetic inputs: 90 tone cases x four dithers, plus four sampling cases in both themes for all five looks with downscale, alpha and fractional off-center crops. Regenerate using `node tools/generate-compact-reference.mjs <Typist checkout>`. Original JS is a test oracle only. The reproducible fixture uses a gzip-compressed JSON resource to retain the full numeric evidence without expanding repository data unnecessarily.

The same portrait PNG gives exactly identical text at 25 x 13 (987 bytes) and 48 x 26 (3,769 bytes), both at defaults and at brightness +0.01 / contrast -0.03 / gamma 2.92 / detail 1, with invert, auto levels and Atkinson. All 20 comparisons (five looks, two sizes, two settings) have zero differing characters. Local source, reference/actual TXT and PNG, results and a side-by-side image live under `artifacts/compact-looks-comparison`. Both columns use the same glyph renderer to isolate conversion from font appearance. Chrome also verifies copied browser text against original JS at both Steam sizes and both control sets for every look. Real social posting remains unverified.

Verification: 612 engine/CLI, 77 API and 88 Web tests pass; TypeScript and production Web/WASM build pass. All three affected compact Chrome journeys and the separate portrait clipboard comparison pass. The isolated published NuGet consumer passes. Earlier unchanged full Chrome evidence covers the other workspaces.

Decision 0015 and the owner's follow-up define this task. With SDK 10.0.403, Magick.NET 15.0.0, magick-wasm 0.0.46 and React 19.3.1, native Rune, UTF-8, Math and casts meet the engine needs. Base UI 1.9.0 [Number Field](https://base-ui.com/react/components/number-field) provides step buttons, keyboard use and commit semantics; installed source confirms pointer-release behavior. [React state identity](https://react.dev/learn/preserving-and-resetting-state) and [effect cleanup](https://react.dev/reference/react/useEffect) explain independent workspaces and Worker lifetime. Installed ImageMagick declarations settled native/browser page-reset differences.

Full-look learning objective: preserve arithmetic/store precision between JavaScript and C#. JS evaluates in double precision but Float32Array rounds every store; C# explicitly casts stored values to float while retaining double expression evaluation. Reference-generated tone/text fixtures failed before the port and pass afterwards. Integer summed-area analysis avoids information lost by an intermediate RGB byte resize. The media adapter remains ImageMagick and deterministic numerical analysis belongs to the shared engine. A character, its UTF-8 budget and its display geometry are distinct; matched fonts/scales are necessary to judge conversion visually. No new dependency was needed.

The expanded oracle replaces five former assertions tied to the simplified Soft behavior (double precision and manual-mode bypass of small-grid assistance). Reference outputs now cover fractional alpha in both polarities for all five looks; the neutral luminance property is tested above the small-grid-assistance range with exact Float32 stores. Fully transparent final-dot checks cover all looks and dithers. Shared arithmetic lives in tone filter/curve/edge modules; each look has its own preparation module, with focused Texture equalization and Sketch line extraction modules. The sampler and browser binding are now source-based for every look, so the Photo-only branch and TypeScript crop/resize path are removed.

The test fixture uses native [.NET 10 GZipStream](https://learn.microsoft.com/en-us/dotnet/api/system.io.compression.gzipstream?view=net-10.0) rather than adding a compression dependency. The pinned source is hash-checked before generating the oracle. Portrait comparisons use the original JS directly; both image columns use the same glyph renderer and scale. Decoder/color-management and external paste fonts remain separate from the demonstrated conversion equality.
